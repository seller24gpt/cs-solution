# 온라인 셀러용 CS 음성접수/요약 시스템 구축안

## 1) 결론: 구현 가능 여부
가능합니다. 요청하신 흐름(1번=음성 문의 접수, 2번=직접 연결 요청, 통화 종료 후 자동 전사/요약/시간기록/대시보드 관리)은 현재 국내 환경에서도 충분히 구축 가능합니다.

핵심은 **IVR(ARS) + 녹취 + STT + 요약 LLM + DB + 관리자 화면** 6개를 연결하는 것입니다.

---

## 2) 목표 업무 흐름(권장)
1. 고객이 대표번호로 전화
2. IVR 안내 멘트 재생
   - 1번: 문의 음성 남기기(기본/우선)
   - 2번: 상담원 연결 요청(후순위)
3. 1번 선택 시
   - 비프음 후 최대 N초 녹음
   - 종료 시 음원 저장
   - STT로 텍스트 전사
   - LLM으로 요약/카테고리/긴급도 추출
   - DB에 `인입시각, 발신번호, 전사문, 요약, 상태` 저장
4. 2번 선택 시
   - 즉시 연결 대신 "콜백 우선" 정책 적용
   - 업무폰으로 순차 발신 또는 예약 콜백 큐 등록
5. 관리자가 대시보드에서 처리 상태 업데이트
   - 신규/처리중/완료/재통화필요

---

## 3) 시스템 구성도(간단)
- **전화/IVR 레이어**: 국내 착신전환 또는 클라우드 콜 API
- **백엔드**: 수신 이벤트 처리, 녹음 파일 저장, 비동기 작업 큐
- **AI 처리**:
  - STT(음성→텍스트)
  - LLM 요약(요지/요청사항/감정/긴급도)
- **데이터 저장**:
  - 통화메타(시간/번호/선택번호)
  - 전사문/요약/처리상태/담당자
- **대시보드(Admin)**:
  - 엑셀형 목록 + 필터 + 검색 + 다운로드

---

## 4) DB에 꼭 저장할 필드(요청사항 반영)
- `call_id` (고유값)
- `inbound_at` (년도/월/일/시/분/초)
- `caller_number`
- `ivr_choice` (1 또는 2)
- `recording_url` (음성 파일)
- `transcript_text` (전사문)
- `summary_text` (요약)
- `intent_tag` (배송/교환/환불/상품문의 등)
- `priority` (low/medium/high)
- `callback_requested` (bool)
- `callback_number`
- `status` (new/in_progress/done)
- `handled_by`
- `handled_at`

---

## 5) “전화 연결은 후순위”로 만드는 운영 정책
가장 중요한 포인트는 기술보다 **정책**입니다.

- IVR 멘트에서 1번을 먼저/강조:
  - "문의는 1번에 남겨주시면 순서대로 가장 빠르게 처리됩니다."
- 2번 선택 시에도 즉시 연결 대신:
  - "현재 상담이 많아 콜백으로 접수됩니다. 급한 건은 1번 음성문의가 가장 빠릅니다."
- 업무시간 외에는 2번을 비활성 또는 콜백 접수만 허용
- 동일 번호 반복 인입 시 우선순위 자동 상승

## 6) 국내 저비용 착신전환/전화 인프라 추천 방식
정답은 한 업체가 아니라, 아래 2단계로 고르는 것이 비용 안정적입니다.

### A안(초기비용 최소): 통신사 착신전환 + 간단 IVR
- 대상: 빠르게 시작하고 싶은 경우
- 구성:
  1) 현재 업무폰 번호 유지
  2) 통신사 착신전환 부가서비스 사용
  3) IVR 가능한 번호(050/070/대표번호)로 전달
- 장점: 설정 간단, 초기 구축 속도 빠름
- 단점: 고급 통계/시나리오 한계

### B안(확장형): 클라우드 콜 API + 자체 대시보드
- 대상: CS쉐어링 대체, 자동화/분석 강화
- 구성:
  1) 대표번호 인입
  2) API 기반 IVR/녹취/웹훅
  3) 자체 AI 파이프라인 연결
- 장점: 자동화/커스터마이징 강함
- 단점: 초기 설계 필요

### 국내 서비스 고를 때 체크리스트(중요)
1. **국내 번호 제공 가능**(050/070/대표번호)
2. **IVR 키입력(1/2번) 지원**
3. **녹취 파일 API 제공**
4. **웹훅(통화종료 이벤트) 제공**
5. **발신번호 정책/개인정보보호 대응**
6. **월 기본료 + 분당요금 + 착신전환요금 총합**

> 요금은 프로모션/약정에 따라 자주 바뀌므로, 최종 계약 전 반드시 3개 업체에 같은 트래픽 조건으로 견적 비교하세요.

## 7) 실제 세팅 절차(처음부터 끝까지)

### 1단계. 전화 시나리오 확정
- 안내 멘트 문안 확정
- 1번 녹음 제한시간(예: 120초)
- 2번 처리 정책(즉시연결/콜백큐)

### 2단계. 번호/착신 인프라 개통
- 대표번호 또는 전용번호 개통
- 기존 업무폰에서 착신전환 설정
- 업무시간/비업무시간 라우팅 분리

### 3단계. IVR 구성
- 환영멘트 업로드
- DTMF 입력 분기(1,2)
- 1번 → 녹음
- 2번 → 콜백 큐 또는 제한적 연결

### 4단계. AI 파이프라인 연결
- 통화종료 웹훅 수신
- 녹음파일 다운로드/보관
- STT 실행
- 요약/태깅 실행
- DB 저장

### 5단계. 관리자 화면 구축
- 컬럼: 인입시간, 고객명(수기/CRM연동), 발신번호, 콜백요청, 처리경과, 진행상태
- 필터: 날짜/상태/태그/미처리
- 엑셀 다운로드

### 6단계. 알림 자동화
- 미처리 30분 경과 시 알림
- 긴급도 high 즉시 푸시/문자
- 동일번호 반복 인입 경고

### 7단계. 법적/보안 점검
- 녹취 고지 멘트 포함
- 개인정보 보관기간 정책
- 접근권한/다운로드 로그 관리

## 8) MVP(최소기능) 권장 범위
2주 내 시작하려면 아래만 먼저 만드세요.
- IVR 1/2 분기
- 1번 녹취 저장
- STT + 3줄 요약
- 목록 화면(시간/번호/요약/상태)

이후 고도화:
- 문의유형 자동분류
- 자동답변 초안 생성
- 고객별 이력 묶음
- SLA 리포트

## 9) 예시 IVR 멘트(전화 연결 후순위 반영)
"안녕하세요. 문의는 1번에 음성으로 남겨주시면 가장 빠르게 확인 후 연락드립니다. 상담원 연결 요청은 2번을 눌러주세요."

"현재 상담량이 많아 순차 콜백으로 접수됩니다. 급하신 경우 1번 음성문의가 더 빠르게 처리됩니다."

## 12) 요청하신 번호 기준 실제 연결 시나리오(010 → 070)
아래처럼 구성하면 됩니다.

- 고객이 **010-2571-7669 (CS 업무폰)** 으로 전화
- 통신사 착신전환으로 **070 업무번호(IVR 수신번호)** 로 자동 전달
- 070 번호에서 ARS 실행
  - 1번: 음성 문의 녹취
  - 2번: 직접연결 요청(후순위 정책 적용)
- 통화 종료 이벤트를 API(Webhook)로 수신
- 녹취파일을 STT로 전사 + LLM 요약
- 전사/요약 결과를 CS 처리 화면에 자동 생성

> 포인트: 고객은 기존에 알던 010 번호로만 전화하면 되고, 실제 자동화는 뒤에서 070/API 시스템이 수행합니다.

### 착신전환 기본 설정 순서(실무)
1. 010 번호에서 통신사 착신전환 부가서비스 활성화
2. 착신대상으로 070 IVR 번호 등록
3. 무응답/통화중/항상전환 중 운영정책에 맞게 선택
4. 테스트콜로 IVR 멘트/DTMF(1,2)/녹취 저장 확인

## 13) “처리 체크 + 답변 내용 기록” 화면 필수 항목
원하신 “처리했는지/미처리인지 + 어떤 답변을 했는지 작성” 기능은 아래 필드로 구현합니다.

### CS 처리 테이블 추가 컬럼
- `processing_status` (미처리/처리중/처리완료/재문의)
- `response_channel` (콜백/문자/카톡/이메일)
- `response_note` (상담원이 실제로 안내한 답변 내용)
- `action_note` (내부 처리 메모)
- `resolved_at` (처리완료 시각)
- `resolver_name` (처리 담당자)
- `follow_up_required` (후속조치 필요 여부)
- `follow_up_due_at` (후속조치 예정일시)

### 화면 UI 구성
- 좌측: 인입목록(시간, 번호, 요약, 상태)
- 우측: 상세패널
  - 전사 원문
  - AI 요약
  - 답변 작성란(`response_note`)
  - 내부메모(`action_note`)
  - 상태 변경 버튼(미처리→처리중→완료)

## 14) 메인 홈 대시보드 구성(요청 KPI 반영)
메인 홈에서 아래 지표를 카드 + 차트로 노출하면 됩니다.

### 상단 KPI 카드(일별)
- 일별 CS 인입 수
- 일별 처리 완료 수
- 일별 미처리 수
- 당일 콜백 요청 수
- 평균 첫 응답 시간
- 평균 처리 완료 시간

### 차트/통계(권장)
- 시간대별 인입 추이(막대)
- 문의유형 비율(도넛: 배송/교환/환불/기타)
- 상태 분포(미처리/처리중/완료)
- 담당자별 처리 건수
- 반복 인입 번호 TOP N
- 주간/월간 처리율 추이

### 실무용 경고 위젯
- 24시간 이상 미처리 건수
- high 우선순위 미처리 건수
- 재문의(동일번호 7일 내 2회 이상) 건수

## 15) MVP에 바로 추가할 실전 요구사항(이번 요청 반영)
기존 MVP에 아래 4개를 반드시 포함하세요.

1. **010→070 착신전환 연동 확인 페이지**
   - 마지막 라우팅 성공시각, 실패로그 확인
2. **처리 체크박스 + 상태 변경**
   - 미처리/처리중/완료를 한 번에 변경
3. **답변 작성란 필수화**
   - 처리완료 시 `response_note` 미입력이면 저장 불가
4. **메인 대시보드 3대 지표**
   - 일별 인입수 / 처리수 / 미처리수

## 16) 구현 우선순위(2주 플랜)
- **1주차**
  - 010→070 착신 + IVR 1/2 구축
  - 녹취 저장 + STT 전사 + 요약 저장
  - CS 목록/상세(전사·요약 표시)
- **2주차**
  - 처리상태 변경/답변입력/담당자 기록
  - 메인 대시보드 KPI 3종 + 기본 차트
  - 미처리 알림/콜백 큐

이 플랜이면 먼저 운영에 투입하고, 이후 고도화(자동분류/CRM연동/고급리포트)를 붙일 수 있습니다.

## 17) 070 번호 서비스 선택 가이드(국내 비교)
요청하신 "070 번호 서비스 어디가 좋은지"는 **가격만** 보면 실패할 가능성이 높고, 아래 4가지를 같이 봐야 합니다.

1. IVR/녹취/API(웹훅) 기능 적합성
2. 분당 통화요금 + 번호/회선 기본료 + 녹취보관비 총합
3. 장애 대응(국내 기술지원 응답속도)
4. 추후 확장성(상담원 추가, CRM 연동, 통계)

### 비교 프레임(추천)
아래 3가지 유형으로 견적을 받으면 의사결정이 빠릅니다.

- **유형 A: 통신사 070 + 착신전환 중심**
  - 장점: 초기비용 낮고 개통 빠름
  - 단점: 고급 API/웹훅/자동화가 약한 경우가 많음
  - 추천 상황: 먼저 저비용으로 시작하고 운영 데이터를 모을 때

- **유형 B: 클라우드 콜센터 SaaS(국내)**
  - 장점: IVR/녹취/상담이력/기본 통계가 즉시 사용 가능
  - 단점: 커스터마이징 한계, 기능별 추가 과금 가능
  - 추천 상황: 개발 리소스가 적고 빠른 런칭이 필요할 때

- **유형 C: CPaaS(통화 API 제공사) + 자체 대시보드**
  - 장점: 요청하신 010→070→Webhook→STT/요약 흐름을 가장 유연하게 구현 가능
  - 단점: 초기 구축/운영 난이도 존재
  - 추천 상황: CS 자동화/통계/업무 맞춤화를 핵심 경쟁력으로 가져갈 때

### 업체 상담 시 필수 질문 12개(그대로 보내도 됨)
1. 070 번호 개통비/월 기본료/최소약정은?
2. 수신·발신 분당 단가와 과금 단위(초/분)는?

5. 녹취 파일 URL/API 제공 가능한가?

### 최종 추천 방법(실전)
- 1순위: **기능 적합성(IVR+녹취+웹훅/API)**
- 2순위: **총비용(기본료+통화료+녹취보관)**
- 3순위: **장애 대응/지원 품질**

즉, 한 줄 추천은 다음과 같습니다.
- **지금 빨리 시작**: 유형 B(SaaS)
- **장기적으로 자동화/대시보드 고도화**: 유형 C(CPaaS+자체 구축)

원하시면 다음 턴에서,

- 실제 미팅용 **업체 문의 메일 템플릿**
까지 바로 만들어드릴 수 있습니다.
